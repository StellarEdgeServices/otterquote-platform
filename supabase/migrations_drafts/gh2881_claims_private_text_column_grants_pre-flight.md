# Pre-flight: gh2881_claims_private_text_column_grants (Tier 3B)

NOT APPLIED. Refs #2881, #2559, #2882, PR #2880 (review 6256187448 finding D2). Needs REVIEW + LEGAL-READ + R-177 signature, an R-097 24-hour notice and a Tier 3B window before any apply. **Stacked on PR #2880** (the redaction helper it reuses is not on main yet).

## 1. What it does
`authenticated` loses SELECT on `claims.homeowner_notes`, `claims.urgency_reason`, `claims.project_confirmation`; every other column keeps today's access. The claim owner and admins read the three through `public.claim_private_text(claim_id)` (SECURITY DEFINER, one row or none). INSERT/UPDATE privileges, policies, `service_role`, and postgres-owned definer functions and views (`bidder_claim_summary`, `accept_bid`) are untouched. Why this and not a policy or a view: see the forward file header (a row policy cannot hide columns for one shared role; a view cannot close the base-table door).

## 3. Callers that would break at apply: moved in this PR (gate still applies)
A `select=*` or a bare `.select()` after an insert/update (RETURNING *) from a browser session fails with 42501 once the columns are gone. The 13 sites found by a scan of `.from('claims')` statements (excluding tests) now name an explicit column list (every `claims` column except the three; 128 columns at 2026-10-19; one shared constant `react-app/app/lib/claim-columns.ts`, the same literal inlined in the static pages):

Where the owner needs the notes (the dashboard edit form, the project-confirmation restore) the page reads them through `claim_private_text()`. The dashboard never saves a blank over notes it could not read (`__privateTextLoaded`), which is why **the RPC (step 1) must be applied before the pages are published**.
`tests/gh2881-claims-no-star-select.mjs` (wired into e2e-tests.yml) fails if any client file selects `*` (or nothing) from `claims`, names one of the three in a claims select list, or lets an inlined list drift from the shared constant; run against the pre-change tree it reports exactly the 13 sites (negative control).
Edge functions (enumerated, FIXED comment on #2881): `python3 tests/gh2881-ef-no-caller-jwt-claims.py` scans all 301 non-test `.ts` files under `supabase/functions` (helpers included) and classifies every `createClient(...)` whose key is not a service-role secret as a caller client: 19 calls, of which 17 carry the caller's JWT (Authorization header in any case, or the caller token passed as the key) in 17 functions: approve-payout, approve-warranty-drift, create-measurement-order, ga4-report, get-business-lines-dashboard, get-homeowner-list, get-payout-completion-status, mark-job-complete, mark-loss-sheet-reviewed, mark-payout-paid, record-warranty-upload, reject-payout, reject-warranty-drift, send-measurement-ready, submit-partner-w9, switch-contractor, verify-payment-method; the other 2 are the anon-key clients in auth-uniform (no caller JWT). Every one is used for `.auth` only, never `.from()`, `.rpc()` or a helper that does. All 33 functions that query `claims` do it through a service-role client (including the `select('*')` reads in create-docusign-envelope, create-payment-intent and switch-contractor), which keeps full access. The script is a regression guard against accidents, not a proof against an adversary. It strips comments with a literal-aware tokenizer, binds each client to the `const|let|var <name> =` or `<expr>.<prop> =` immediately before its `createClient(` (so a typed `Deno.serve(async (req: Request) => {...})` wrapper, a ternary, or `ctx.db = createClient(...)` bind correctly), accepts a generic argument list (`createClient<Database>(...)`), and follows aliases and a client passed into a helper up to 3 levels. Every identifier bound to `createClient` is itself scanned as a client constructor: `const mk = createClient`, a default parameter `makeClient: typeof createClient = createClient`, or `{ makeClient: createClient }`. That is the shape in send-message-notification, process-hover-rebate, notify-contractors and send-support-email; all four build their client from the service-role key, so they are service clients and keep full access, and the guard fails if one is switched to an anon or caller key (the tree fixtures below do exactly that to the real files). A factory that returns a caller client (function, arrow, or the lazy `getClient = () => (client ??= ...)` form) only counts as scanned when every call site is either assigned and its uses checked, or used for `.auth` only; `mk(tok).from(...)`, `getClient().from(...)` and passing the result to something unknown fail. The guard also fails if any caller client is not bound to something it scanned (19 of 19 here); a tree-wide mutation run (injecting `.from("claims")` after every `.auth` use) flags all 19. 27 mutation fixtures must fail it, 11 clean fixtures must pass, and 4 tree fixtures (the real files above with the service key swapped for the anon key) must fail; it is wired into e2e-tests.yml. Accepted residuals, not chased: a service-role key combined with the caller header held in a separate variable, and `createClient as cc` renames. Production catalog: no view or function other than `bidder_claim_summary` depends on the columns.
